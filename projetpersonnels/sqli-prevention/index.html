< Prévention des injections SQL >

Projet personnel : mise en place de bonnes pratiques de développement sécurisé pour réduire le risque SQLi.

Contexte

Objectif : démontrer une approche défensive (validation d’entrées, requêtes paramétrées, séparation des responsabilités).

Le projet fournit un script d’exemples et une structure de tests pour illustrer les erreurs courantes et les corrections.

Objectifs

  • Réduire le risque d’injection via des requêtes paramétrées
  • Structurer une validation d’entrées côté applicatif
  • Documenter des patterns sûrs et réutilisables

Démarche

  1. Revue des bonnes pratiques (OWASP, patterns de requêtage)
  2. Écriture d’exemples “mauvais” vs “corrigés”
  3. Tests de non‑régression et documentation

Compétences mobilisées

  • Sécurité applicative
  • SQL & bases de données
  • Rigueur de test
